# 企业案件门户演示版设计

## 目标与范围

在现有 Open Self Service 仓库内提供一个中文、可点击的前端演示版，覆盖登录注册、公司与办理人绑定、案件权限、进展、资料、报表、筛选和树状列表。演示地址为 `/en/demo`；`en` 是当前项目已有的路由语言前缀，页面内容使用中文。保留现有首页、登录页、NestJS API 和数据库行为。此阶段不接入 Zoho CRM、邮件服务、文件存储或真实 PG 消息推送。

演示应能在只启动现有 Next.js 前端、具备当前项目要求的基本环境变量时访问。不得依赖 NestJS API 返回演示数据。所有演示数据均为虚构示例，不使用真实客户、邮箱或案件信息。

## 用户流程

1. 初次打开显示演示登录、注册入口及演示账号提示。预置两家公司、各自的管理员和普通成员，以及可注册的“PG 办理人邮箱”名单，均使用 `.example` 域名。预置账号统一使用仅供演示的 `Demo123!` 密码；用户可选择预置账号登录。
2. 注册时输入名单中的邮箱并设置密码。页面显示一次性模拟验证码，输入正确后建立本地演示用户，自动绑定名单对应的公司及模拟 PG 办理人 ID。无名单邮箱、错误验证码和重复注册给出明确提示。验证码只在当前注册会话有效，不发送邮件。
3. 用户可查看和修改演示个人资料；更改密码需先输入当前密码。账号数据在浏览器刷新后保留。密码只保存带随机盐的派生摘要，不保存明文；整个过程仍属于本地模拟认证，不可用于真实环境。
4. 管理员可以查看本公司成员并逐案勾选其可见权限。普通成员只能查看获授权案件，不能打开权限编辑入口；管理员可查看本公司全部案件。预置普通成员至少获得一个案件的查看权，新注册普通成员初始无案件权限。公司之间的数据在演示视图中互不显示。所有权限都只在前端执行，不能视为生产安全边界。
5. 案件页支持公司 → 项目 → 案件三级展开，案件详情展示基础字段、进展时间线、资料和通知。用户可按关键词、状态、阶段、类型、地区、负责人、日期范围筛选，并排序。列表使用虚构的常见字段：案件编号、案件名称、所属公司、项目、类型、地区、负责人、优先级、阶段、状态、提交日期、最后更新、截止日期。后续拿到字段文档后再调整正式字段。
6. 点击“模拟 PG 更新”会把选定案件推进到下一阶段并生成通知；刷新后仍保留。此按钮显式标记为演示操作，不接收真实推送。
7. 用户可选择 PNG/JPEG 图片及 CSV/XLS/XLSX 表格，校验类型和 10 MB 上限，形成待审核记录。管理员可通过“模拟 PG 审核”将记录标记为通过或退回并填写理由。浏览器只保留文件名、类型、大小、所属案件与审核状态，不保存文件内容；刷新后仍能看到记录，但不能重新下载文件。
8. 报表基于当前用户可见案件计算总数、状态/阶段分布、逾期数量和近期更新，筛选口径与案件页一致。权限或模拟进展变更后，报表随之更新。

## 页面与数据边界

- 新增 `[locale]/demo` 路由及独立演示界面，不复用现有 NextAuth 登录或 CMS catch-all 页面。页面由总览、案件、资料、报表、成员权限、个人资料几个工作区组成，保留清晰的导航与退出入口。
- 演示逻辑封装在 `apps/frontend/src/features/portal-demo/`：类型与种子数据、浏览器持久化、纯函数选择器、注册与账号操作、各工作区组件。页面路由只负责挂载演示入口。
- 使用一个带版本号的 `localStorage` 状态对象保存演示账号、当前会话、权限、案件进展、通知和资料元数据。首访写入虚构种子数据；结构版本不匹配时重置为当前种子并提示用户。提供“重置演示数据”按钮。存储不可用或损坏时回退到内存状态并提示；不覆盖仓库现有持久化数据。
- 状态读取必须在客户端挂载后进行，避免服务端渲染和浏览器状态不一致。展示层只从“当前用户可见案件”选择器读取案件、资料、通知和报表数据；任何跨公司或未授权案件 ID 均被拒绝。该限制是演示行为，不具备服务端安全保证。
- 后续真实接入时，以 NestJS API Harmonization Server 对接 Zoho CRM：替换本地账号验证、公司/办理人映射、案件读取、资料上传、审核与事件同步。界面组件继续依赖领域数据类型，不直接依赖 Zoho SDK。

## 验收标准

- `/en/demo` 可直接访问，原有页面路由不受影响；中文界面适配桌面及窄屏。
- 注册、模拟验证码、登录、退出、个人资料和改密可操作；错误输入有可理解的反馈。刷新后账号及状态保留，页面不持久化明文密码或文件内容。
- 管理员调整本公司成员的案件权限后，成员登录看到的树、列表、详情、资料、通知及报表同步变化；跨公司案件不可见。
- 树状展开、搜索/组合筛选、排序、案件详情和“模拟 PG 更新”可操作，变化在刷新后保留。
- 资料类型/大小校验、上传元数据、模拟审核与退回理由可操作；报表只统计当前用户有权查看的案件。
- 运行前端类型检查、相关单元测试与浏览器端到端演示验证。只在后续实施阶段执行这些检查；本设计阶段不修改应用代码。

## 明确限制

模拟验证码会显示在页面上，不发送真实邮件；本地密码摘要、前端权限、上传记录和“审核”均不能用于生产。浏览器数据可被用户修改或清除，换设备不会同步。真实 Zoho 字段、组织关系、推送协议及文件审核流程需要在正式对接阶段另行确认。
